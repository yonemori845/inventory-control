# 📊 プロジェクト全体像・開発計画の理解

## 🎯 プロジェクトの目的

在庫注文管理システムの開発を通じて、以下を実現します：

1. **在庫管理の一元化**: 商品の在庫を効率的に管理
2. **バーコードスキャンによる効率化**: 手作業を減らし、ミスを削減
3. **売上データの可視化**: 経営判断を支援するダッシュボード
4. **PWA対応**: モバイルデバイスでも使いやすい

## 🗂️ データモデル設計

### Google Spreadsheet構造

#### 1. products（商品マスタ）
```
| productId | name | barcode | price | category | createdAt | updatedAt |
```
- **主キー**: productId（UUID推奨）
- **ユニーク**: barcode
- **用途**: 商品の基本情報を管理

#### 2. inventory（在庫）
```
| productId | quantity | minStock | lastUpdated | updatedBy |
```
- **外部キー**: productId → products
- **用途**: 在庫数量とアラート閾値を管理

#### 3. orders（受注）
```
| orderId | productId | quantity | unitPrice | total | status | orderDate | updatedAt |
```
- **主キー**: orderId
- **外部キー**: productId → products
- **ステータス**: pending, processing, completed, cancelled
- **用途**: 注文情報を管理

#### 4. sales（売上）
```
| saleId | orderId | productId | quantity | unitPrice | total | saleDate |
```
- **主キー**: saleId
- **外部キー**: orderId → orders, productId → products
- **用途**: 売上データを集計用に保存（ordersから生成）

#### 5. users（ユーザー権限）
```
| userId | email | role | createdAt |
```
- **主キー**: userId
- **権限**: admin, user
- **用途**: ユーザー権限を管理

## 🔄 主要な業務フロー

### 1. 商品登録フロー

```
ユーザー操作
  ↓
商品登録画面で情報入力
  ↓
バーコードスキャン（オプション）
  ↓
API Route: POST /api/products
  ↓
Google Sheets API: productsシートに追加
  ↓
在庫シートに初期在庫を追加
  ↓
完了
```

### 2. 受注フロー

```
ユーザー操作
  ↓
バーコードスキャンで商品を追加
  ↓
注文カートに商品を追加
  ↓
数量を入力・変更
  ↓
注文確認
  ↓
API Route: POST /api/orders
  ↓
Google Sheets API: ordersシートに追加
  ↓
在庫数量を減算
  ↓
完了
```

### 3. 売上登録フロー

```
注文ステータスを「完了」に変更
  ↓
API Route: PUT /api/orders/:id
  ↓
売上レコードを作成
  ↓
Google Sheets API: salesシートに追加
  ↓
完了
```

### 4. 在庫更新フロー

```
在庫一覧画面で商品を選択
  ↓
数量を入力（増減）
  ↓
API Route: PUT /api/inventory/:productId
  ↓
Google Sheets API: inventoryシートを更新
  ↓
在庫アラートチェック
  ↓
完了
```

## 🔐 セキュリティ設計

### 認証・認可フロー

1. **ユーザー認証**
   - Google OAuthでログイン
   - NextAuth.jsでセッション管理
   - JWTトークンで状態保持

2. **API Route保護**
   ```typescript
   // すべてのAPI Routeで認証チェック
   const session = await getSession()
   if (!session) {
     return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
   }
   ```

3. **権限管理**
   - usersシートで権限を管理
   - admin: 全機能アクセス可能
   - user: 閲覧・在庫更新のみ

### データ保護

1. **環境変数管理**
   - `.env.local`で機密情報を管理
   - Gitにコミットしない（`.gitignore`に追加）

2. **サービスアカウント**
   - JSONキーを安全に管理
   - 最小権限の原則（エディター権限のみ）

- 一度に全データを読み込まない

- 無限スクロールまたはページネーション実装

## 🚨 重要な制約事項

### Google Sheets API制限

1. **レート制限**
   - 1分あたり60リクエスト（デフォルト）
   - 1日あたり300リクエスト（無料枠）
   - **対策**: キャッシュとバッチ処理

2. **パフォーマンス**
   - 10,000行を超えると遅くなる可能性
   - **対策**: ページネーション、インデックス設計

3. **同時更新**
   - 複数ユーザーが同時更新すると競合の可能性
   - **対策**: 楽観的ロック、タイムスタンプチェック

### バーコードスキャン制約

1. **ブラウザ互換性**
   - HTTPS必須（localhost除く）
   - モバイルブラウザで動作確認が必要

2. **カメラ権限**
   - ユーザーが明示的に許可する必要がある
   - 権限拒否時のエラーハンドリング必須

## 🎯 実装の原則

1. **小さく始める**
   - 各ステップで最小限の機能を実装
   - 動作確認してから次に進む

2. **段階的拡張**
   - 基本機能が動作してから拡張機能を追加
   - 一度に多くの機能を実装しない

3. **エラーハンドリング**
   - すべてのAPI呼び出しでエラーハンドリング
   - ユーザーフレンドリーなエラーメッセージ

4. **テスト駆動**
   - 各機能の動作確認を徹底
   - 特にAPI Routesのテストが重要
